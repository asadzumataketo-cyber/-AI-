# JRA × NAR Racing AI — 中央競馬・地方競馬2軸予測研究

JRA中央競馬およびNAR地方競馬（当面はサラブレッド平地競走）について、発走前に利用可能なデータだけを使って各馬の着順確率を推定し、結果と比較する研究プロジェクトです。帯広のばんえい競馬は競技方式が異なるため初版では対象外。

> **Status:** ローカル週末E2E基盤を実装。100,000回の予測・追記保存・結果照合に対応。実レース4件の予測は未実施、モデルは未校正です。実行手順と制約は [ローカル実行手順](research/LOCAL_RUNBOOK.md) を参照してください。従来のJS200回版は元ワークスペースに保持しています。

## 実装優先順位（2026-10-28 第3回評議会：JRA先行を最優先）

**Phase1: 10/31〜11/1 JRA中央競馬4レースで予測ドライランを実行し、11/4のJRA Ver.1.0を目指す。** Phase2: JRAの安定稼働と時系列検証を確認した後、地方競馬NARの研究・移植を進める（NARは未着手でも初版の完成判定を妨げない）。地方競馬は開催頻度が高く研究用途で価値があるため破棄せず保留。

- [週末テスト Issue #12](https://github.com/asadzumataketo-cyber/-AI-/issues/12)
- 対象：10/31（土）東京11RペルセウスS・京都11RファンタジーS、11/1（日）京都11RまほろばS・東京11R天皇賞（秋）。当日公式に再確認する。
- 発走60〜30分前の予測時点で全馬の確率・seed・入力の出典・タイムスタンプ・モデルバージョンを固定し、レース後に結果照合。
- 4レースは機能の端から端までの動作検証。予測優位性や回収率は証明できない。仮想予測のみ。

## Ver.1.0（目標: 2026-11-04）

- 第1段階では適法に取得したJRA出走表・過去走データをローカルに取り込む（NARはPhase2）
- 直近3走・補正走力・距離・馬場・位置取り等に基づくJRAの基本予測（NAR固有の補正はPhase2）
- NumPy による **100,000回** モンテカルロ試走（10,000回×10バッチ）
- 各馬の1着・2着・3着・3着以内確率、3連単Top10
- 予測時点（as_of）、出典、乱数シード、モデルバージョンを保存
- JRAの結果を取り込んで時系列バックテスト（Log Loss / Brier Score / 校正）を実施。NAR別の評価はPhase2。

## 開発原則

1. **未来情報の混入を防止。** 回顧記事・確定結果・確定後オッズは同一レースの事前予測に使わない。
2. 10万回は乱数による標本誤差を減らすための設定であり、予測精度を保証しない。
3. 8GB RAM のWindows PCを想定し、バッチ化してメモリを抑える。
4. 普段の数値処理は Python/DuckDB で完結し、Codex・ClaudeなどLLMの利用枠を節約する。
5. 無断記事転載・規約違反の収集・有料データの無許可共有をしない。生データや鍵はコミットしない。
6. JRA・NAR・競馬場ごとに、オッズだけの基準予測と比較し、独自モデルの性能改善を確かめる。
7. 競馬研究・予測検証が目的。利益や回収率の達成は保証しない。

## 予定技術構成

Python / NumPy / DuckDB / pytest。画面やクラウド同期の採用は既存実装を確認した後に決めます。

## 2軸モデル設計（2026-10-28の第2回評議会で追加）

- **共通基盤:** Python/NumPyの10万回モンテカルロ、DuckDB、予測保存、時系列評価、UIを共有。
- **JRA専用:** 中央の芝/ダート、クラス・時計・競馬場/馬場適性の特徴量推定。
- **NAR専用:** 地方の所属・地区・クラス、コース内外/右左、競馬場当日の速度バイアス、先行力・位置取り、馬場特性を個別に推定。多数レースで裏付けがない重みは固定しない。
- **クロスリーグ:** 転籍馬と交流競走では、所属履歴と対戦水準の差を推定し、不確実性を明示。
- **評価:** 市場（JRA/NAR）・競馬場・コース条件別にサンプル数、欠損率、Log Loss、Brier Score、校正を記録。総合的中率だけで比較しない。
- **NARのPhase2スコープ:** 中央の実装と検証を安定させた後、大井・船橋のサンプルから検証開始。11月4日の初版にNAR稼働は必須としない。
